# First release readiness

Status on 2026-11-19 is **verified prerelease awaiting final owner review**. [Version 0.0.1](https://github.com/p33nah/loopo/releases/tag/v0.0.1) is public as a prerelease. Signed installation, same-key replacement, production model setup, cancellation, retry, and cached offline initialization have passed. The owner confirmed a voice command setting the signed app to 80%. The owner chose an encrypted Desktop backup on the same PC, with recovery credentials stored separately. Acceptance of the coverage limits below and official promotion remain owner actions. [Release record #77](https://github.com/p33nah/loopo/issues/77) contains the current results.

The hardening work adds automated verification before further product features. Each result must name the commit and executed check. A missing check remains open even if the build succeeds.

### 16 KB runtime evidence (2026-11-12)

Tested the source tree for merge commit `42a15b0` (`a01a75706c60c582f5a90001ce0bc1b131f40fff`) using a debug APK with SHA-256 `BE53B0721BF54544AC4A0AE473C4DCA779078803879079F1B8D4B111748255E0`. The Android 15/API 35 x86_64 emulator used the `google_apis_ps16k` image; `getconf PAGE_SIZE` returned `16384`, and the image fingerprint was `google/sdk_gphone16k_x86_64/emu64xa16k:15/AE3A.240806.043/12960925:userdebug/dev-keys`. The emulator setup and repeatable commands are in [testing.md](testing.md#android-15-16-kb-runtime).

The APK verifier separately confirmed 16 KB ELF and ZIP alignment for every ARM64 and x86_64 native library, and 4 KB ELF alignment for the 32-bit ARM libraries. This is packaging evidence, not runtime evidence.

- First full instrumentation run: native bridge, fractional-loop, WAV, and MediaCodec cases passed. The process then crashed during `viewModelInspectsDecodesAndRestoresGeneratedWaveSessionAcrossLifecycle`: SIGSEGV/null dereference in a JIT frame for `CoroutineContext$DefaultImpls.plus`, with the stack originating in the waveform scan. The test passed when isolated.
- Second full instrumentation run: 18 tests passed. `nativePlaybackKeepsAdvancingWhileActivityIsStopped` failed after activity recreation because playback was no longer reported active. The WAV session test passed in this run.
- Isolated retry of the session test passed. Isolated retry of `nativePlaybackKeepsAdvancingWhileActivityIsStopped` timed out waiting for playback to start. Logcat showed successful Oboe/AAudio stream open/start, then repeated emulator audio-HAL `pcm_writei ... I/O error` and an Oboe callback STOP.

The emulator demonstrates native library loading and several playback-control paths under a 16 KB page size. Its audio backend did not provide stable end-to-end playback, and the app-level suite was not consistently green. This gate remains open until the runtime checks pass on a functioning 16 KB audio target; ARM64 physical-device verification is also outstanding.

### 16 KB runtime follow-up (2026-11-13)

Built the Loopo source from `27daad2f33764731d9832e3c42e8d12535eaac22` on Windows. The debug APK SHA-256 was `3B281EB969C14AAEB6C7574C0B4BB83301FB043A1C16E729F5E2ECC712165EF5`. Emulator 37.2.13 ran the same Android 15 x86_64 image listed above and reported `16384` bytes per page. Both the debug and unsigned release APKs passed `zipalign -c -P 16 4` and the ELF and ZIP checks in `scripts/verify_apk.py`.

- The guest's `tinyplay` failed to play a generated WAV directly through VirtIO Sound with the default host backend and with `QEMU_AUDIO_DRV=wav`. Disabling `VirtioSndCard` left this image without a recognized sound card.
- With the WAV backend, Windows captured PCM from the instrumentation runs. The capture contained the 440 Hz fixture tone. Logcat also reported repeated Ranchu audio HAL `pcm_writei` I/O errors, so the capture proves that some audio reached the virtual output.
- The first instrumentation attempt ended before any test with an Android startup ANR. A later attempt passed 14 tests before ART aborted in `Profile Saver` at `copied_methods_start <= methods->size()`. The session test passed on the next attempt. The underlying cause of the ART assertion and the earlier JIT SIGSEGV is still unknown.
- Another full Windows run passed 20 of 21 tests. The background playback case failed with `positionFrame=480000`, `isEnded=true`, and `error=null`. Its 10-second fixture ended before the assertion. The test now loops the fixture and waits for the source cursor to change while the activity is stopped.
- On [Linux with 16 KiB pages](https://github.com/p33nah/loopo/actions/runs/43420251078), Android 15 instrumentation terminated twice before completing a test. Android 16 completed 21 of 21 tests on its second attempt, with 440 Hz PCM in the QEMU capture. That run disabled Android's 16 KiB backcompat settings. The APK hashes, runtime fingerprints, instrumented results, and filtered logcat are in the run artifacts.

The Android 15 emulator has demonstrated native loading, transport controls and partial PCM output at 16 KiB. The issue stays open pending repeatable Android 15 playback with stable audio. ARM64 runtime and physical audio routes remain unverified.

Play, Pause, seek, rate, and marker controls worked. Reinstalling the same APK with `adb install -r` preserved the file, A at 0:05.63, B at 0:21.24, and rate at 71%. These results do not close every hardware and failure-path check. Physical ARMv7, sustained lifecycle checks on a second manufacturer, wired removal, storage/provider failures, and small/large-screen coverage remain as listed above. The Android 15 x86_64 16 KiB emulator remains unstable. The owner must review and accept this release scope before official promotion.

Time/frame conversions now use checked arithmetic. Remaining source risks include delayed detection of truncated WAV payloads, best-effort session saving during abrupt process death, and playback transitions not covered by automated evidence. Resolve reproduced defects with focused regressions. Keep assumptions about vendor codecs and output routes labeled until physical evidence exists.
